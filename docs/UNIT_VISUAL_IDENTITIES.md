# 16 兵种视觉身份规范

## 范围与实现

本轮针对“同身体、换武器/换色”的识别问题重画轮廓，不改变战斗规则。三个实际配置的 `coder` 子代理分别实现步兵、轻装/远程/骑乘/器械、施法者；主侧统一像素工具、接入、审查文案并执行验收。

- 源帧 **48×48**、四帧循环、共用脚底锚点、朝右、左上光源。
- `src/render/units/pixelArt.ts`：整数栅格、统一材质和阵营色。
- `infantry.ts` / `mobile.ts` / `casters.ts`：不同职业的独立轮廓与动作。
- `src/render/sprites.ts`：分派、缓存、图鉴肖像；渲染器负责敌方镜像、受击闪烁和死亡倾倒。肖像保留完整源格，不裁掉冠盔/高法器。
- 两阵营共用几何，不以不同剪影暗示阵营有隐藏数值差异。

## 文案与规则边界

16 个名称、定位名、能力文案及所有机械字段保持原值。只调整故事、战术提示，以及盾卫的描述，使其符合真实装备与伤害规则；故事仍为每条 60–110 字的短背景。

- 民兵确实持**短矛**，不再保留“画剑却写短矛”的矛盾，也不误删真实装备。
- 所有兵种都可由两阵营征募，故事不把某种兵写为单阵营专属。
- 刺客/斥候没有新绕路、隐身、挑选后排或穿墙能力；“善战目标”不等于新增索敌逻辑。
- 禁卫是移动迟缓而非“只守不追”；火法有溅射而非自动瞄准最密集位置。
- 祭司的施法动作是治疗表现，不承诺造成攻击伤害。首击、治疗、克制、攻城倍率均沿用既有代码。
- `src/data/unitRules.test.ts` 对照重画前机械字段快照；`content.test.ts` 检查故事长度、装备锚点、共同征募及不存在的能力措辞。

## 量化辅助证据

`docs/metrics/unit-visual-redesign.json` 锁定画师、调度器、数据、渲染器及审计脚本源码 SHA。640 帧 = 16 兵种 × 2 阵营 × 5 动作 × 4 帧。审计检查空白、整数 alpha、放大画布重画后的越界裁切、四帧动画变化、双阵营几何一致；另比较全部 120 对兵种，以及事先指定的九组易混淆组合。

同原点、alpha≥128 掩码的 IoU（越低表示几何重合越少）：

| 原问题组合 | 改造后 idle / 12 姿态均值 |
| --- | --- |
| 民兵 / 盾卫 | 0.538 / 0.532 |
| 盾卫 / 执誓者 | 0.558 / 0.584 |
| 盾卫 / 禁卫 | 0.697 / 0.693 |
| 禁卫 / 执誓者 | 0.530 / 0.545 |
| 斥候 / 刺客 | 0.448 / 0.456 |
| 轻骑 / 重骑 | 0.792 / 0.798 |
| 术士 / 祭司 | 0.541 / 0.547 |
| 术士 / 火法 | 0.636 / 0.638 |
| 祭司 / 火法 | 0.533 / 0.535 |

事先设定的九组 idle/均值门槛均为 `<0.86`。这不是玩家辨识率；轻重骑保留马体共性，仍是九组中最接近的一对，不声称完全消除拥挤遮挡下的误认。

阵营着色报告 `factionInk` 使用 `cloth + light + gold` 像素比例（idle 约 14.3%–30.7%），**没有计入 dark**；不与不同口径的代理初测百分比混用，也不把任一百分比包装成人类可辨阈值。职业辅色只辅助识别，阵营仍以蓝/红衣布、盾面、鞍布与旗布为主要锚点。
