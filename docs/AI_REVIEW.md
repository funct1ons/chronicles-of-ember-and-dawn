## 结论先行

1. **大师确实不够难，不是资源作弊问题。** 普通对战中双方同一套金币、收入、人口、征募规则，难度只改变决策评分权重和随机性。大师主要是“无噪声的同一启发式”，不是更深的规划。战役 c10 的公开资源奖励另算，不应作为公平大师指标。
2. **原报告的“纯斧击败大师”主要是测试调用时机错误。** 旧脚本在收入到账前选兵，实际游戏在到账后选兵。真实规则下纯斧 0 胜 / 10 负；但 **mixed 对大师 20 胜 / 0 负，纯长枪 10 胜 / 0 负**，仍是可靠漏洞。
3. 核心根因是**经济边际收益失真、伤害模型与战斗不一致、按单兵而非整波/出兵后阵容评分、盾兵评分吸引子**。缺少有效火力和治疗协同，而不是缺钱。满人口时还会锁死在原阵容。
4. **友军阻塞已复现**：64人口的八路弓墙阵型，后面16斧兵或8禁卫在120秒内一次攻击都没有；移除弓墙后近战前排恢复攻击。普通六兵扩散测试不能覆盖它。
5. **未证实活跃战斗存在持续的同带敌军穿透**；但有真实的投影后退瞬移、单帧左右次序残留，以及回合上限帧生成重叠单位。不能把这些统称“穿兵”，也不能声称所有情况已安全。
6. **纯盾的正常合法玩法有明显拖局**：10 局中 7 平、9 局打满 80 波（约 954 秒）。不能只靠缩短上限掩盖。

## 3. P0：经济和伤害评分根因

### 3.1 经济分不是实际增收，封顶/禁增长后仍当经济兵

位置：`ai.ts:153-164,200-201`；真实购买：`simulation.ts:187-202,287-298`。

当前经济分 `income/cost * 340 * econWeight` 不读己方当前收入、growth、实际能买几个、剩余波数的现金兑现，也不读人口占用时长。结尾 econWeight 仍为0.5。

微场景：相同阵容、900预算下，把收入80换600、growth从1换0，评分完全一样。例如固定八盾对八斧、900预算、第12波：crossbow **214.91**、shield **190.36**，四种收入/增长组合完全相同。实际收入600或growth0时新增收入都应为0。挑战 h2 正是合法的 growth0 场景。

**最小修正方向**（必须与 planWave 的取整/上限语义一致）：

```ts
n = min(18, floor(gold / cost), floor(freeSupply / supply));
gain = min(max(0, 600 - currentIncome), round(n * unitIncome * growth));
// 只计以后还会结算的增量现金；满收入、growth=0、无后续结算时均为0。
```

不要直接把旧单兵总分乘 n：那会把廉价铺场偏好放大。应评估“整波加入后的边际阵容价值”，同时计入花费、人口和生存时间的机会成本。

### 3.2 原始轻/重伤害不等于有效DPS

`ai.ts:161-164` 不调用 `computeDamage`，忽略防御、盾减远程物理、魔法无视防御、长枪反骑、刺客后排加成、冲锋等。固定加分不能可靠弥补差异。

实际单次伤害（`micro.json.damageExamples`）：

| 攻击者 | 打 axe | 打 shield | 打 pike |
|---|---:|---:|---:|
| levy | 2 | 2 | 11 |
| shield | 5 | 2 | 11 |
| axe | 50 | 47 | 28 |
| bow | 4 | 2 | 23 |
| crossbow | 40 | 22 | 16 |
| mage | 48 | 48 | 35 |

大师对轻甲 pike 与 levy/runner 的关键候选分数相同（pikes字段只抑制骑兵等特定候选），没建模长枪多出的射程、生存力与实际交战方式。对重甲盾与斧也缺少敌方实际防御区分。`Profile.hp/shields` 等虽已收集，却没进入有效威胁/克制评价；healer 还会以135射程计入“远程人数”，并获得不实际用于攻击的9伤害估值。

建议：直接复用有效伤害计算，按敌方可接战单位的剩余HP/威胁/人口合理加权；计入能开火的比例、接敌时间和射程，而不是每个轻甲都同权。治疗单独按缺血、持续损耗、覆盖距离、过量治疗计算，不能伪装成DPS。

只替换临时 master 策略，其他评分和真实战斗完全保留；相同五种子换边，各10局，以下为 **AI胜/负/平**：

## 4. P0/P1：盾吸引子、死区、整波过量补位和人口锁

位置：`ai.ts:163-206`。

### 4.1 严格死区与经验死区要区分

- **guardian 在全兵表的大师评分中被 shield 严格支配**：两者所有角色/压力/补位奖励一致；盾的收入/金币更高，每人口韧性项105.6 vs78.83，轻/重每人口DPS也都更高。禁卫能买时盾必能买，copies奖励不低；禁卫最多多6分的末尾人口贴合奖，远不足以逆转。故不是“偶尔没选到”，而是当前公式保证不选（禁盾白名单例外）。
- 5,376个全兵表场景（16敌兵种×4数量×7己方阵容×6阶段×远近）中，从不胜出：**rider/knight/mage/healer/ballista/assassin/guardian/paladin**。除guardian外，这只是测试空间内未覆盖到，不是全状态数学证明。
- 真实180局大师对手（20 mixed +160单兵）的征募总计也只涉及另外8类：shield6184、levy2351、runner2193、bow846、firemage416、crossbow404、pike143、axe1。上述8类一个都没招。

因此“为法师/治疗/刺客写了分支”和“分支会选中且有效”完全不同。至少为每个设计角色建立全表可达正例，再决定究竟修评分还是兵种数据。

### 4.2 seed73 的真实逐波证据

mixed 对大师，第18波结束：玩家基地2500，大师0；玩家花3854金，大师花7672金；击杀119:32。**双方都600收入，不是大师经济起不来**。大师实际招56盾、27runner、18bow、9firemage、9levy，没有治疗、普通法师或刺客。

- 前几波：`levy → runner → runner → bow → shield → runner → bow`。
- 第11波己方近战4/远程9：盾 **270.94**，开始按缺前排补盾。
- 第12波只剩一名远程：改 firemage；第13波又补盾；之后反复盾/火法。
- 第15波己方归零、敌方8近战22远程：盾 **256.02**，刺客 **200.00**。先重建大量低输出盾，而不是可持续的反后排阵容；很快再次归零。

纯枪对大师：第2/3波 runner **227.44/227.14**，bow **226.45/225.89**，极窄分差使大师先用近战斥候正面接枪；第17波盾278.04压过其他候选，后期大量盾/火法，最终第27波败。微型单挑中 bow 可以击败 pike，axe/mage/firemage 等也能击败它；这不是“游戏不存在克制枪的手段”。单挑不等价于等预算阵容，不能据此直接定数值。

### 4.3 整波与人口效应

- 每波只选一种，但常一次招9盾/3火法/若干治疗。评分只是当前阵容的“缺一个角色”固定奖，不评估补整波后是否过量；也没计入远离前线的兵何时抵达。
- 按单兵人口效率排序，却只给预算 copies 最多9分，实际能招1个和18个的战场贡献近似处理。
- 盾兵存活久、低输出，人口满后死亡只腾2人口；法师要4、火法要6，刚腾出的2人口又被盾填满，形成转型锁。不能简单靠多给金币解决。
- seed73纯盾对大师，第35波后大师常6000金、80人口、选levy但实际招0；第52至60波连续如此。这里的“levy选择”只是无可招时的fallback，不应统计成实际民兵出兵。第61波空4人口，仍选两盾而非转型。

建议：评分按 **postArmy** 的前排有效HP、可射击DPS、治疗能力和接战时间做饱和/递减收益；补位奖励应在达到目标后归零，不是整波仍享受固定奖。当前返回unitId接口可保留，枚举每种候选的整波结果即可。需要转型时允许同规则保留空人口，等足4/6再买关键兵；不要每波强行用廉价兵填缝。进阶再加入有预算的2–3波预测，而不是加固定反枪特判或难度资源倍率。

## 5. P1：阵型、索敌与碰撞

### 5.1 友军满宽度火力墙使短手重近战长期不能参战

位置：`simulation.ts:535-669`。

复现：8路各一名己方bow在x575；后方2排×8路axe（或1排×8路guardian）从x500排起；敌方8个耐久guardian在x720（高HP、禁其攻击，用于隔离移动；不是胜率样本）。弓+斧、弓+禁卫各64人口，敌方48人口，均未超过默认80人口。跑120秒：

| 前方有弓墙 | 后排兵种 | 发生攻击的后排兵 |
|---|---|---:|
| 否 | axe | 8/16（前排可攻击） |
| 否 | guardian | 8/8 |
| 否 | pike | 16/16 |
| 是 | axe | 0/16 |
| 是 | guardian | 0/8 |
| 是 | pike | 16/16 |

弓手安全停火，后排卡在x560附近，最后纵向移动发生在约第3–12秒，此后直到120秒都不能自行脱困。八个lane均被占，强制换道没有真正绕行通道。枪的48射程能隔友军出手，斧/禁卫不能。高HP只保证观察窗口，不改变阻塞规则；这是队形保持时局部近战没有自解锁机制，不是“整场无任何伤害”，也不能据有限测试断言正常战局永远不会因死亡/队形变化解锁。证据：`legal-jam.json`；另有超默认人口的40近战压力场景，仅作补充。

根因：forwardLimit 对所有友军同样阻挡，缺少远程让位/前排优先权；换lane只是找另一条同样堵塞的线。仅增加换道频率解决不了满宽度阻塞。

建议：前排追敌时远程/治疗按局部需求让位，预留近战通道；出生/到达阵型按角色排布；基于同一帧快照算期望移动，再解约束，避免数组顺序抢占。不能简单关闭友军碰撞，那会把堵塞变成无限堆叠。验收要看**每个应接战单位最后有效攻击时间**，不只看总体基地是否掉血。

### 5.2 索敌保护不是合理的物理遮挡

位置：`simulation.ts:419-510`。

- `pickEnemy` 用 `abs(dx)+42*lane差+0.25*abs(dy)`，不优先可攻击目标。微场景：bow(500,375)、敌guardian(650,315)、敌mage(740,375)：guardian距离约162在185射程内，mage240在外，弓仍锁mage而不射guardian。应先评估射程内可达目标，再评估追击目标，并设置目标保持/切换阈值。
- 所有兵种都被“距敌军本lane最前单位90以后不可选”硬过滤，连远程也一样；不看攻击者是正面还是已从别lane绕后。assassin(795,375)、敌guardian(600,375)、敌mage(810,375)仍选195外的guardian，不选身边15外mage。这个人工场景验证过滤语义，不能当作已自然发生的突入频率证据。
- 最前单位可能是骑兵/远程/治疗，并非真正挡在攻击路径的前排；因此硬过滤不等于近战不可穿透约束。

建议将**身体通行约束**与**攻击可选目标**分开：近战按真实可达/接触路径选敌；远程依设计处理可射目标，不因另一lane或攻击者身后的“前排”获得全局免疫。刺客克制若要成立，也必须有实际可达后排的移动/目标规则。

### 5.3 不是已证实的普遍穿兵，但确有瞬移/单帧残留

测试：5种兵的32v32耐久密集阵列各30秒（含axe、guardian、bow、crossbow、mage），未见同带跨敌；另对真实 mixed/axe/pike/shield 各3种子逐帧检查：

- **活跃战斗**按游戏最小中心间距13检查：上述12局既未见持续敌方重叠，进一步对已有存活单位做双向逐帧线性扫掠，也未发现扫掠过程中心距离<13的穿体（`swept.json`）。这不等于已验证贴图像素或所有大dt场景。
- 两局pike各出现1帧同14宽带左右次序倒置；其中还记录到一次两帧均在14带内的x次序反转，但最近中心距离仍≥13。换道/出生后的局部次序不能直接当成穿过敌人身体；13与14两种判据要区分。
- `forwardLimit` 可以把原本不想动的mage瞬间向后推15：x967.9067 →952.9067，原因是几乎同x的友军healer进入y带。其意图位移本来为0，根因是无下界地 `nextX=min(desiredX,limit)`，而非速度。
- `separateEnemies` 按阵营强制左右顺序，单次pair投影而非接触前相对方向。seed73盾局 t530.833s，单次分离把一名盾 x644.308 →558.213，**一帧后退86.095**；盾正常每帧前进仅0.767。此时敌军通过别lane绕行后再聚拢，会被拉回阵营规定的左右位置。

建议：基于帧初相对位置处理接触法向/扫掠碰撞，有限迭代解决多体约束；修正位移要受明确限幅并计数。友军横移的冲突优先在横向解决，不把纵向投影传播成几十像素后退。加入大dt(0.1)、边界、交叉lane、多体及数组顺序置换测试。**本轮没完成所有初始布局穷举和UI视觉验证，不能保证任何情形都不穿透。**

证据：`micro.json`、`legal-jam.json`、`probes.json.motion`、`followup.json.physics`、`terminal.json`、`swept.json`。

### 5.4 治疗和先手偏差

- `healAlly`（835-854）候选循环不断缩小 bestDistance，较远重伤单位可在比较缺血前被过滤。固定近盾249/250、远禁卫100/600：仅调换数组次序，一次治疗从近盾 **+1** 变成远禁卫 **+24**。建议先在完整射程内按缺血/濒死权重比较，distance只作次级tie-break，并测试置换不变性。
- `performAction` 按数组依次结算，先手杀死后手则后手不反击。对称单挑可固定偏向先加入的一方；镜像胜负不能只归因AI。建议明确这是设计还是实现偏差，必要时同tick伤害先收集后统一结算；指标至少做换边和真正几何镜像。低档随机决策与出生位置共用RNG，换难度也会改变后续出生分布，不能把同seed不同难度看成同一布局的严格因果实验。

## 6. P1：上限帧和拖局

位置：`simulation.ts:321-356,374`。

第N波：先结算、买兵、spawn，然后立即按基地HP结束。**第N波没有一帧作战机会**。maxRounds2的最小复现：第一波t6.033，第二波t18.033生成后立刻draw，场上30兵。真实80波同理在t954.033结束。

这也解释部分“穿兵/重叠”假象：纯盾seed17/73/806终局帧分别有2/5/4对敌军中心距离<13，都是**已经winner非空的最后spawn帧**；游戏直接返回，未经过移动/分离。最深中心距离仅约0.309。不能把它们混进活跃战斗碰撞缺陷统计，但终局视觉/状态仍应修。

建议：最大N波仅限制招募次数，给第N波完整作战窗口后再裁决（不要生成第N+1波）；用明确结束原因 `baseDestroyed / roundLimit / draw` 记录，报告draw率、上限率、中位及P95时长。若保留基地血量裁决，明确同血即平，不暗加大师优势。

纯盾7/10平局里双方基地均2500；另2局仅靠第80波基地微差判负。它们是盾低伤害+人口锁/补位策略问题，不是单纯把上限80改120就会解决。首要让AI能转型破盾，其次才考虑**双方同规则、公开的**加时机制，且必须重新验收所有单兵和射程策略。

## 7. 建议执行顺序与公平验收

### 最小落地顺序

1. **修指标入口/时序**，保留当前33局作legacy回归；40波和80波分开标注，不覆盖旧证据。
2. **修评分语义**：真实边际增收 + computeDamage有效伤害；独立回归后再组合。保持同资源、同白名单、同人口、同招募上限，别上难度资源/伤害倍率。
3. **改成整波边际阵容价值**，加入补位饱和、有效射击覆盖、前排剩余HP、治疗需求和人口预留。这一步比单独调大counterWeight更重要：放大它也会放大“缺前排→继续买盾”的错误。
4. **修满宽友军让位、目标可达性、治疗排序、碰撞投影**，每项用微场景独立验证，不用一个综合胜率掩盖另一个机制问题。
5. 再考虑大师专用的有限候选预测/2–3波搜索；只能读公共状态，不能偷看玩家尚未公开的下一波选择或未来随机数。分支比较用独立克隆，不能污染正式BattleState、rng或隐藏的运行时移动状态。难度差异优先体现在规划深度/误判率，而非资源特权。
6. 最后才调兵种数值。先验证等金币/等人口、混合阵型中的实际优势，再决定guardian等是否自身弱；不要为迁就错误评分把所有贵兵盲目加强。

### 不是上线承诺的建议验收门槛

- 使用至少50个训练种子、另外50个未调参种子；全部换边。master-normal胜率明显高于当前，建议预设≥75%非平局胜率且换边差<10个百分点，报告区间，不只报点估计。
- 对16种固定单兵、mixed、反应式克制策略、带治疗阵型、经济后转型等策略库同时测；建议固定单兵胜大师≤20%，任何一个≥80%即阻断发布。没有有限测试能证明“永无万能单兵”，至少避免只针对当前pike硬编码。
- 正常允许的纯盾也纳入拖局指标；建议draw<5%、到上限<10%，但不要靠胜负裁决作弊达到。单独报告防守策略与一般组合军，避免均值稀释。
- 覆盖growth0、收入600、金币6000、空人口0/1/2/4/6、限制白名单、playerSide1、各供应上限和战役公开bonus；每种战略角色要有**全兵表**可达正例。guardian若仍不可达，应明确重做评分/定位。
- 现有 `ai.test.ts:134-159` 克制测试删掉shield等竞争候选，证明不了全兵表选择；fixture把 `laneOfY(315+...)` 返回的0..7当y坐标传给addUnit，应传实际世界y（或 `laneCenterY(lane)`），再增加完整候选集测试。
