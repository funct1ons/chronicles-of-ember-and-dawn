# Miragine War 经典机制研究

研究日期：2026-10-22。方法：网页直读、搜索可见片段与独立资料研究。**没有运行原版 Flash，也没有反编译 SWF。** 本文严格区分网页证据、推断和原创规则。当前官方网站兼有手游下载入口，不能把它单独当作2011版本所有细节的证明。

## 有资料支持的核心机制
1. 红蓝双方横向战争，选择兵种自动交战，以摧毁敌方水晶为目标；不手动控制每位士兵。
2. 选择的是下一次生产的兵种，倒计时归零且金币足够时自动生产。官方原句：“当时间为0而金钱足够出兵的话，士兵就会自动出击。”
3. 生产会增加后续经济。官方原句：“每出一个兵都会增加金币数，累加的金币将在下一回合给玩家。”因此新增收益至少不是本次立即无限再投资的余额。
4. 原版存在金币、收入、单位供给消耗、不同单位生命/护甲类型/对轻重甲伤害/攻击距离等属性。早期玩家策略强调先达到供给上限再切更昂贵单位。
5. 玩家不能直接点选购买任意指定数量；选择类型，由资源自动决定数量。
6. 16兵种名单在 Flash 介绍和Speedrun攻略交叉一致：Newbie、Veteran、Zombie、Samurai、Sword Man、Ninja、Novice、Heavy Sword Man、Monk、Vampire、Cavalry、Immortal、Mage、Iron Knight、Dread Lord、High Lord。
7. Speedrun攻略表中 Newbie 与 Samurai 的 RR 为20%，高阶 High Lord 为10.6%，支持“低阶经济效率更高、高阶投入时机重要”的策略方向。这是二手攻略数值，**本作没有直接移植**。

## 必须保留的不确定性
|问题|结论|
|---|---|
|回合准确秒数|单一Wiki提到29秒，未运行确认，不把29/30/20任何值宣称为已确认原版常数。|
|每波出兵数量|推断为金币与供给共同约束，类似min(floor(金币/费用),floor(供给/消耗))；具体遍历与取整顺序未知。|
|金币与收入精确结算顺序|官方只证明出兵增益延至下回合；并不足以证明Flash内部“先加收入还是先扣生产费”的精确代码顺序。网上“回合内立即扣金生产”的说法与倒计时出兵描述冲突，不采信为事实。|
|人口补充|有供给约束，但每波重置、随时间增长、存活单位持续占用的精确规则未证实。手游120/110人口不用于Flash结论。|
|收入与金币上限|早期评论“8k per round”意义含混，不确认为任一上限。|
|索敌与碰撞|自动推进与交战确认；最近目标、锁定、换目标、前排遮挡、寻路细节均未确认。|
|阵型|无法直接手动摆放；由波次顺序与移动速度形成前后排是合理推断。精确生成网格与是否可隔排攻击未知。|
|原版全部属性|Wiki存在Computer/Mobile两套数值且相互冲突，拒绝用摘要反推全表。|

## 本作明确原创与调整
- 原创埃瑟兰世界、16个原创兵种、要塞代替水晶、四个战场、10关战役与3个试炼。
- 初始准备6秒、正常波次12秒，固定30Hz模拟。所有数值来自 `src/data/units.ts` 与 `src/data/missions.ts`，不是原版数据。
- 本作顺序：**领取已有收入 → 按所选单位批量征募 → 扣金币 → 增加后续收入**。新收入不会回到本波无限招募。
- 本作采用**存活单位持续占人口、死亡释放**，不是声称复刻原版人口重置规则。这个调整用于控制规模、强化战线支援取舍。
- 默认人口80、收入上限600、金币上限6000、每波最多18单位；软八队列用于规模、碰撞与信息可读性。
- 护甲减固定值、近战前沿目标优先、法师无视防御、盾抗远程、长枪反骑、首击冲锋、治疗/范围攻击/攻城倍率均为本项目规则。
- 80波战争时限按基地血量结算（相同则平局）。AI不调用在线服务；难度提升决策质量而非隐藏资源。战役非对称资源明确告知。

进一步高保真研究需要合法可运行的原版、帧级观察或源代码证据。本次不为追求看似精确而虚构这些证据。
